## 实现范围

1. 显式 `runtime.root_branch` 与 `workspace_id` 启用 Requirement 远端模式，根仓 URL 复用已批准 `analysis.source`。固定批准 SHA 和单次解析的当前分支 SHA 分开读取，校验契约文件集合、正文、Schema 及归档唯一性。
2. Prepare 在 Task 自有临时根仓真实 clone、OpenSpec Archive、限定路径提交、push，由独立 TFS Git API 回读。确认发布后删除本次临时 clone；故障重试直接读取已发布归档。
3. Writeback / Complete 使用固定 SHA 的归档 API 工件，不依赖 Project、旧根仓或 Engineer 绝对路径。Evidence 使用 `repo_key + repo_url + 完整 SHA`，核对 TFS Collection、PR 和候选身份。
4. 复用既有 pending、子任务映射、TFS 写入标记、摘要 ID 和 Done 流程；未新增 Archive Commit Metadata 或分布式锁。
5. Git 使用兼容沙箱的 BusyBox MinGit；PAT 仅经精确仓库 URL 范围的子进程环境注入，不进入 argv、磁盘或全局凭据配置。仅 clone 上限调整为 1200 秒，其他命令保持 300 秒。

实现复核见 [implementation-review.md](M10-e2e/implementation-review.md)，调用配置见 [远端工件说明](../../../workspace-skills/finalize-delivery/references/remote-artifacts.md)。

## 失败记录与修复

- 沙箱内 Git Credential Manager 枚举失败 `0x5`：改用已有 TFS 配置提供进程级认证，未关闭沙箱。
- 根仓浅克隆超过 300 秒：对照探针实际 Git 子进程约 618 秒完成，成功 Prepare 首条命令约 497 秒。仅 clone 放宽到有界 1200 秒。测试子进程配置 TFS 的 NO_PROXY；这不证明代理是原故障根因，也不要求 Git protocol v0。三个控制端诊断 clone 经路径、分支、HEAD、干净状态核对后清理；Runtime 失败诊断目录保留。
- Windows `node --import` 不接受原始 `D:` 路径：测试驱动改用 `pathToFileURL(...).href`，保留原失败报告。
- 首次 Writeback 恢复被 TFS `OriginalEstimate Required, InvalidEmpty` 规则拒绝：原报告、日志已备份。仅对映射、标题、父子关系核对通过的测试子项 264845，以 revision CAS 补充测试估算 1h，在 History 标明“fixture 管理数据，非生产实际研发工时”。没有修改产品代码猜工时或绕过规则；之后在真实 Runtime 重跑通过。
